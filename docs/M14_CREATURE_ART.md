# M14 regional creature families — art and implementation

Built-in image generation was used (imagegen skill); no CLI/API fallback. Existing hedge goblin artwork supplied the painted Mernodna style reference. Full source figures were generated, visually inspected, refined where leg leads/anatomy were unclear, and copied into the project. No old upper bodies were stitched onto new limbs. The numbered spider anatomy guide is an authoring reference ONLY and is not drawn in the game.

## Behavior and geography

- Trandum goblins: atomic groups of two hedge scavengers plus one stone-slinger, near woodland margins and abandoned crown freight, not inside working farms or towns. One authored persistent freight encounter; existing saved two/three-member groups upgraded without resetting original HP/defeats. Native surviving groups restore against their home habitat rather than becoming permanently dormant after a brief chase into adjacent terrain.
- Narenthil thornlings: two to four, restricted to the Old Greenward Stones and Moon Pilgrims' Clearing corruption areas. Two authored persistent groups in clearings outside the protected marker radius. Not scattered through healthy elven gardens/settlements.
- Narenthil grove spiders: two to four, in forest away from roads and protected settlements. One authored clearing nest near Moon Pilgrims' Clearing. No web barrier, poison stack or additional gameplay system was invented for this slice.

All use existing encounter IDs, group alerts, short home leashes, idle cohesion, ally-aware chase approaches, scenery/actor collision, level scaling, XP, shadows, target markers and save/chunk streaming. Dead member records now remain until their entire group is defeated, so corpse pruning does not turn a wounded group into an apparently undersized group for a later migration.

Stone-slingers use the existing ranged standoff, clear-line checks, windup/cancellation/recovery and an actual painted 12-world-unit stone. Spear and stone shots share ONE eight-slot pool with finite range/TTL, committed release aim and swept obstacle/player checks; no extra per-family pool or homing/trails. Stone speed/range/TTL: 260/600/2400ms. Spears retain 330/780/2600ms. Both now aim from the actual release position to the committed target instead of retaining a feet-derived trajectory after applying a hand-height offset.

Existing quieter human/wraith audio is reused for goblins/thornlings; spiders intentionally do not borrow mammal or ghost vocals. Existing restrained swish/impact effects remain. Attack release/rake/bite is scheduled at 600/480/300ms, with 400/320/450ms recovery respectively. Boss art, quest IDs, dialogue and cutscenes were not replaced by this milestone.

## Loading and memory boundary

M14b–d are NOT prepared at boot. `M14ArtResidency` loads source PNGs serially on regional demand/admission, prepares an atlas and registers animations before any actor can activate. At most two of these new atlases are resident. Only unreferenced families can be evicted, with a five-second grace covering transient corpse sprites. Source textures are released after preparation. Shutdown detaches the loader callback, releases actors before atlases, and clears the shared projectile pool before the tiny stone texture.

Raw prepared RGBA costs: slinger 2048×1344 = 10.5 MiB; thornling 2304×1728 = 15.1875 MiB; spider 2560×1536 = 15 MiB. Thus the two-atlas ceiling is approximately 30.19 MiB (not including source/decode temporaries or driver overhead). Stone texture is 64×64 = 16 KiB. The previous M14a atlas remains unchanged. This is resource arithmetic, NOT a measured PC/phone performance claim. Actor and projectile caps are unchanged; spawning is bounded and no new whole-world per-frame scans were introduced.

## Verification boundary

Source code and PNG appearances were inspected; the anatomical guide script was run solely to create an authoring reference image. No automated tests, type checks, builds, gameplay simulations, browser checks or game launches ran. GPU frame coordinates, all-facing proportions, hand/feet registration, actual stone hits/cancellation, streamed loading/eviction, save/reload and device performance remain unverified pending manual acceptance or explicit test permission. M14a–d source implementation is complete, not declared runtime-approved.
